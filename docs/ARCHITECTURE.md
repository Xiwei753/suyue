# GT4 Reader 架构与验收

## 设备与边界

- 手表：HUAWEI WATCH GT 4 46 mm，466 × 466 圆形屏幕。使用 **HarmonyOS Lite Wearable / JS FA**，而不是 Wear OS 或 ArkTS Stage。
- 手机：鸿蒙 NEXT / HarmonyOS 7，使用 **ArkTS Stage**，首先面向 Huawei Pocket 2。
- 工程分开构建、分开签名；共享的是协议文本，并不是可直接互相编译的代码库。
- 不在仓库提交证书、密钥、SDK 二进制包或第三方源码。
- **尚未在 GT 4 和 Pocket 2 真机验证**：手表安装权限、表冠事件、Wear Engine 双端权限/文件上限都属于待测事项。

## 责任划分

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| 手机（apps/phone） | TXT/EPUB 导入、编码归一、章节提取、书库、传输发起、发送状态 | GT 4 屏幕上的复杂排版 |
| 手表（apps/watch） | 书籍落盘、分段读取、圆屏显示、翻页/进度、简单目录 | EPUB 解包、字体解析、联网抓书 |
| 协议（shared/protocol） | 数据结构、切块、校验、传输序号/ACK、错误恢复 | 绑定某个 SDK 的具体 JavaScript/ArkTS API |

## 圆屏策略

- 先把单页正文放入圆内接矩形，以 466px 圆屏为基准，测试初始 316px 宽的安全阅读区；具体尺寸和字号由 GT 4 真机校正。
- 不将正文字行一直延伸到圆边缘，不强行把每一行居中造成难读。
- 优先保证文字不会被裁切、翻页无重复/丢字、长篇文本打开不会一次性载入。
- 表冠事件接入之前，手表演示通过点击翻页；表冠功能当前未完成。

## 传书路线

1. 手机导入 TXT，统一编码成 UTF-8，建立书籍 ID、章节序列、内容长度和校验值。
2. 探测 GT 4 和手机之间可用的 Wear Engine 接口、双端权限、签名与配对关系。
3. 小文件验证：握手 → 发送元数据 → 发送小分块 → ACK → 校验完成。
4. 测定真实最大消息/文件体积，确定分块大小。**不将示例文档中的 4096 字节读文件默认值误认为蓝牙传输上限**。
5. 才开始发送整本书、写入临时文件、完整校验、原子替换，以及断点恢复。
6. EPUB 始终优先在手机解析，手表只接收章节文本和目录信息。
